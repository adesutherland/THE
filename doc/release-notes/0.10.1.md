# CRXTHE 0.10.1

16 November 2026

CRXTHE is an independently maintained fork based on Mark Hessling's THE 4.0.
cREXX remains the default macro engine and is bundled privately with the editor.

## Changes since 0.9.1

- The standard installers compile an optional in-process ooRexx macro bridge.
  Install ooRexx separately, select it at startup, and use the shared Classic
  profile. Regina remains optional and separately installed. Editor commands,
  EXTRACT/functions and stems, EDITV, nested and cached in-store macros,
  Rexx queue operations, READ panels and command-limit halting use the selected engine.
- The shared workbench adds profile-owned actions and menus, named LOG and live
  read-only DOCUMENT panes, staged forms and CTLCHAR file-field projections.
  Revision checks and atomic edit groups protect Apply and conditional Undo.
  Frontends consume the same core-owned definitions; their presentation and
  qualification limits remain documented separately.
- Program console, current-file actions, profile Build/Apply, output-reader
  controls and graphical navigation are aligned around the shared session.
  The browser/Wasm preview and optional GTK frontend retain their own limits.
  Native source-tool execution is qualified on macOS arm64; bounded FILE stdin
  and atomic CREATE output remain native POSIX features, unavailable on Windows
  and browser/Wasm. The native source runner is separate from macro selection.
- LLM protocol input retains queued requests across macro execution and startup
  READ panels. Windows/browser save and buffer-switching checks cover the
  platform's line endings. Release C unit tests retain their assertions.
- Bundled cREXX includes the selected compiler's matching diagnostic catalogues,
  so relocated tools provide explanatory errors instead of diagnostic codes alone.
  Runtime, compiler, assembler, bytecode and messages stay in one SDK cohort.

## Installation and qualification

Use the platform installer or fully extract the portable archive, then launch
`bin/crxthe` (`bin/crxthe.cmd` on Windows). Optional Regina and ooRexx runtimes
are not distributed in the package. See [Windows first use](https://github.com/adesutherland/THE/blob/v0.10.1/doc/Windows-Readme.txt),
[first launch](https://github.com/adesutherland/THE/blob/v0.10.1/doc/first-launch.md) and [interpreter setup](https://github.com/adesutherland/THE/blob/v0.10.1/doc/rexx-interpreters.md).

Automated candidate checks passed 131 tests on macOS and 113 on Windows, with
8 Windows skips retained explicitly. The private compatibility suite passed
121 cases per engine on each host for cREXX, Regina and ooRexx. Third-party
prefix-macro originals, adaptations, ports and patches are excluded from public
packages. ooRexx qualification uses 5.2.0.

Manual Windows installer and visual acceptance remain pending. Automated source
and macro checks do not replace acceptance of the final signed installers.
The browser remains experimental; broader host and frontend limits are listed
in [known issues](https://github.com/adesutherland/THE/blob/v0.10.1/doc/known-issues.md) and the [roadmap](https://github.com/adesutherland/THE/blob/v0.10.1/doc/roadmap.md).
